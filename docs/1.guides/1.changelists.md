---
title: Using changelists
description: Group a messy working tree into separate commits, from the interface or the command line.
---

A working tree that has drifted into three unrelated changes is the case
changelists solve: group the files, then commit one group at a time without
staging and unstaging by hand between commits.

## Group the changes

Create a list and move files into it. A new list becomes the active one on
both surfaces, and the active list is where changes glimpse has not seen
before land — so create the list _before_ starting a piece of work and its
files collect themselves.

A list's name doubles as its commit message, so name it as you would name the
commit.

## Commit one group

Committing a changelist stages exactly that list's files, commits them, and
leaves every other change in the working tree.

**It resets the index first.** Staging done by hand before the commit is
discarded rather than added to it — the list, not the index, decides what goes
in. If you have staged something manually, commit that separately first.

Selecting only some hunks of a file is available at commit time, in the
"Review & commit hunks" dialog. Note what that dialog is and is not: the
selection applies to that one commit and is not stored, so reopening it starts
from the full file again.

## From the command line

The same lists are reachable headlessly through `glimpse cl`, which reads and
writes the same file the app does — so a list created in the terminal shows up
in an open window, and the reverse.

Run `glimpse cl --help` for the subcommands and their arguments; it is the
authoritative list and this page deliberately does not copy it. Two things it
does not tell you:

- **`--json` emits the `changelists.json` contract**, which is the documented
  on-disk shape rather than a rendering of it — so a script consuming it sees
  the same structure the app persists.
- **A running glimpse does not poll this file.** On a working copy under
  `\\wsl$` the watcher is best-effort, so refresh the window (or refocus it)
  after changing lists from a WSL shell.

## Result

The tree is committed as several coherent commits rather than one mixed one,
and the grouping survives running git elsewhere — see
[Changelists](/concepts/changelists) for what happens to your lists when it
does.
